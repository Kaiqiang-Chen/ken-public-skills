# 三版本播客文档输出规范

## 目录

1. 文档结构
2. 结构化精华版
3. 原文润色版
4. 原文无润色版
5. 覆盖与验收

## 1. 文档结构

```markdown
---
播客: <播客名>
单集: <单集标题>
时长: <HH:MM:SS>
转写日期: <YYYY-MM-DD>
来源: <原始节目 URL>
转写引擎: <引擎>
工具: podcast-transcribe skill
---

# <单集标题>

> 阅读说明：本文包含结构化精华版、原文润色版和原文无润色版。

原始节目：[节目链接](<URL>)

## 结构化精华版

### 总结论

<一段话>

**1. <第一个连续议题>**

- <问题、观点、案例、条件和结论>

**2. <第二个连续议题>**

- <问题、观点、案例、条件和结论>

### 可执行清单

- <动作>

### 代表性原话

> <原话> —— <说话人>

## 原文润色版

> 编辑说明：保留完整信息，只做可读性编辑。说话人统一写作 **【姓名】**，不用「姓名：」。

### <本段主题>（<开始时间>—<结束时间>）

**【主持人】**<该轮发言>

**【嘉宾】**<该轮发言>

### <下一段主题>（<开始时间>—<结束时间>）

**【主持人】**<该轮发言>

## 原文无润色版

> 存档说明：以下为转写引擎初始输出。

<未经修改的完整转写>
```

关键约束：

- 三个版本标题（`结构化精华版`、`原文润色版`、`原文无润色版`）是文档中仅有的二级标题，且顺序固定。
- 结构化精华版里，只有 `总结论`、`可执行清单`、`代表性原话` 可以做成标题。议题条目必须用加粗正文（`**1. 标题**`），禁止写成 `###` / `####` 或其他标题层级，以免出现在文档大纲或目录里。议题内部不要再拆更小的标题。
- 原文润色版必须按主题切成带时间戳的小节标题，禁止整期对话堆成没有小标题的一大段。时间范围用中文破折号 `—`，写成 `（M:SS—M:SS）` 或 `（H:MM:SS—H:MM:SS）`。
- 飞书写入时，润色版小节标题使用可自动编号的标题（如 `seq="auto"`），以便大纲显示为 `2.1`、`2.6` 这类编号；精华版议题仍保持加粗段落，不得因此变成标题。

## 2. 结构化精华版

目标是“全量观点的逻辑重组”，不是“精彩内容精选”。

必须覆盖：

- 节目提出的所有主要问题。
- 每位发言人的独立观点和不同意见。
- 用来支撑观点的案例、数据、经验与类比。
- 方法的前提、限制、失败经验和适用边界。
- 话题转折和最终结论。

允许删除：寒暄、纯重复、无语义口头禅、与内容无关的设备或录音插曲。

组织方式：优先沿节目发生顺序；如果原对话跳跃，可用因果关系轻微重排，但不得把后来观点提前到失去语境的位置。

标题层级：

- 允许的标题只有版本标题 `结构化精华版`，以及 `总结论`、`可执行清单`、`代表性原话`。
- 每个连续议题写成加粗段落，例如 Markdown `**1. 开场画像：面无表情的德州玩家与即将卸任的劳模 CEO**`；飞书对应 `<p><b>1. …</b></p>`，后面用无序列表写清问题、观点、案例、条件和结论。
- 禁止把 `1. …`、`2. …` 做成标题；禁止在议题下再分更小的标题。导入飞书后，精华版在文档大纲里应只出现 `总结论`、`可执行清单`、`代表性原话`。
- 议题标题必须能说明内容，不使用“其他”“补充”等空标题。编号从 1 连续递增。

## 3. 原文润色版

保留全部有信息量的发言。润色只服务于可读性：

- 修 ASR 错误和专有名词。
- 删无意义口头禅、口吃和重复半句。
- 补标点、分句、分段。
- 修复说话人边界。

不得总结、删观点、补事实、改变语气强弱或把不确定判断改成确定结论。

### 3.1 分段小标题

把整期对话按主题切成连续小节，每节一个标题，标题后标注该段起止时间：

`<主题>（<开始>—<结束>）`

示例：

- `开场：欢迎与人物引入（0:00—1:12）`
- `商业机会：全球发现需求，向客户体现价值（32:57—38:05）`

规则：

- 每节对应一段连续论述，时间范围与字幕或转写时间轴对齐，各节相连并覆盖整期，不留大段无标题对话。
- 时间用中文破折号 `—`，不要用 ASCII `-`、`--` 或 `~`。
- 标题要说明该段在讲什么，不要用“对话续”“继续”这类空标题。
- 可以和精华版议题大致对应，但润色版按时间线切分，不删内容、不合并掉不同观点。
- 飞书写入时给这些小节标题加上 `seq="auto"`，让大纲自动显示 `2.1`、`2.6` 等编号；标题正文本身不必手写编号。

### 3.2 说话人格式

每轮发言开头使用全角方括号人名，紧接正文，中间不加冒号：

- 正确：`【剑锋】大家好，欢迎来到保持偏见。`
- 错误：`剑锋：大家好`、`[剑锋]`、`说话人0：`

同一说话人连续多段时，只有该轮第一段加 `【姓名】`，后续段落不再重复人名。

本地 Markdown 写作：`**【姓名】**正文`

如果转写引擎输出的是 `【说话人0】`，在润色版里替换成真实姓名（依据节目介绍、片头自我介绍或可靠来源）；原文无润色版保持引擎原样。

同步到飞书时，只给人名着色，不要整段上色。同一人始终同一颜色：

- 第一说话人 / 主持人：蓝色 `text-color="blue"`（也可用已验证的 `rgb(36,91,219)`）
- 第二说话人 / 嘉宾：橙色 `text-color="orange"`（也可用已验证的 `rgb(222,120,2)`）
- 第三人：绿色 `text-color="green"`
- 更多发言人按飞书合法色值轮换（`red` / `yellow` / `purple` / `gray`），一人一色，全文不改。

飞书 XML 示例：

```xml
<p><b><span text-color="blue">【剑锋】</span></b>大家好，欢迎来到保持偏见，我是剑锋。</p>
<p><b><span text-color="orange">【寒芽】</span></b>我是寒芽。</p>
```

## 4. 原文无润色版

直接嵌入转写引擎初始文件。不得进行：

- 拼写修正。
- 说话人重命名。
- 标点恢复。
- 口头禅删除。
- 格式化重写。

可以只在最前面增加存档说明，正文必须逐字保留。

## 5. 覆盖与验收

建立覆盖清单，把润色稿每个自然块映射到结构化议题。验收时至少检查：

- 结构化议题数量与节目长度、话题变化相称。
- 反方观点没有被主结论吞掉。
- 案例和数据在对应观点下出现。
- 原文润色版和无润色版都有开头与结尾。
- 最终文档中存在三个二级标题且顺序正确。
- 精华版议题是加粗正文，不是标题；文档大纲或目录里看不到 `1. …`、`2. …`。精华版大纲只应出现 `总结论`、`可执行清单`、`代表性原话`。
- 润色版有带时间戳的小节标题，不是一大段对话。
- 说话人使用 `【姓名】`，没有 `姓名：` 这种冒号形式。
- 已同步飞书时，不同说话人的人名颜色不同，且同一人颜色一致。
