# Podcast Transcribe 3.1

把一个播客链接变成可核对、可阅读、可分享的完整文档。默认使用本地 FunASR；绝不让摘要或润色覆盖原始转写。

## 最终交付契约

每期必须同时保留四个文件：

1. `<安全文件名>-音频.<ext>`
2. `<安全文件名>-原文无润色版.txt`：转写引擎的初始输出，生成后只读，禁止覆盖。
3. `<安全文件名>-原文润色版.txt`：完整保留信息与发言顺序的可读文字稿。
4. `<安全文件名>-三版本文档.md`：依次包含：
   - `结构化精华版`
   - `原文润色版`
   - `原文无润色版`

如果用户指定知识库目录，写入该目录；否则写入 `~/Documents/播客转文字/`。如果环境已配置 `lark-cli` 且用户需要飞书文档，将最终 Markdown 导入飞书；没有飞书能力时，Markdown 即为完整交付。

输出规范必须读取并遵守 [references/output-contract.md](references/output-contract.md)。

## 工作流

### 1. 解析来源并获取音频

接受以下输入：

- 小宇宙单集 URL
- RSS URL
- 播客名称 + 单集关键词
- 本地音频

优先级：RSS enclosure → 页面内音频直链 → 用户提供的本地文件。

#### RSS

用户给播客名时，用 iTunes Search API 查 `feedUrl`；解析 RSS 的 `<item><enclosure url>`，按单集标题关键词匹配。用户未指定单集时只处理最新一集，不要擅自处理全集。

#### 小宇宙

先打开单集页并读取页面数据：

```js
() => {
  const audio = document.querySelector('audio');
  const next = document.getElementById('__NEXT_DATA__');
  let title = document.title;
  let url = audio?.src || audio?.currentSrc || '';
  if (next) {
    try {
      const ep = JSON.parse(next.textContent)?.props?.pageProps?.episode;
      title = ep?.title || title;
      url = url || ep?.media?.source?.url || '';
    } catch {}
  }
  return { title, url };
}
```

音频直链为空时，等待页面加载后再试一次。仍为空则改查播客 RSS；同一步失败两次后停止并说明原因。

下载后验证：文件必须存在、可由 `ffprobe` 读取、大小通常大于 1 MB、时长与页面信息大致一致。外部内容必须在最终文档保留原始节目链接。

### 2. 本地转写并永久保留原始版本

检查 `ffmpeg` 与 FunASR 环境。默认虚拟环境：`~/.funasr-venv`。

```bash
python3 -m venv ~/.funasr-venv
~/.funasr-venv/bin/pip install -U funasr
```

多人播客默认启用说话人分离：

```bash
~/.funasr-venv/bin/python scripts/transcribe_local.py \
  "<音频>" "<安全文件名>-原文无润色版.txt"
```

单人口播才加 `--no-spk`。

原始文件生成后立即校验非空，并把它视为不可变底稿。后续所有处理必须另存新文件，禁止在原始文件上改写。

### 3. 生成机器预处理底稿

推荐运行本地标点恢复脚本，在严格保留原始说话人边界的前提下补充标点，并清理明显口吃：

```bash
~/.funasr-venv/bin/python scripts/repunc_local.py \
  "<安全文件名>-原文无润色版.txt" \
  "<安全文件名>-机器预处理版.txt"
```

该文件只是润色输入，不能冒充最终文字稿。原始说话人边界如果落在词中或句中，留到下一步按语义人工修复；脚本失败时，直接从原始转写开始人工语义校订，不得省略润色步骤。

### 4. 制作原文润色版

完整读取机器预处理版；没有预处理版则读取原始转写。长文按时间或自然段分块读取，直到全文结束。

润色目标：让读者可以顺畅阅读，同时保留节目全部信息。

必须执行：

- 修正明显 ASR 错字、同音词和中英文专有名词。
- 删除无意义的“呃、嗯、啊、然后、就是、对”等口头禅；有语义时保留。
- 合并口吃、重复词、重复半句和自我纠正产生的冗余。
- 重建标点、句子和适中段落；说话人变化时另起段。
- 修复说话人标签切在词中或句中的情况，按完整句子重新归属。
- 保持口语访谈感，不改成文章，不拔高，不添加原文没有的事实。

禁止执行：

- 不得总结、删减观点或省略案例。
- 不得为了“顺”而改变结论、数字、立场或因果关系。
- 不确定的专有名词先查节目简介、Show Notes 或可靠来源；仍不确定则保守保留并标记 `[待核]`。

完成后写入 `<安全文件名>-原文润色版.txt`。对比原始版本，确认开头、结尾、主要案例和发言人都存在。

版式必须遵守 [references/output-contract.md](references/output-contract.md) 第 3 节：

- 说话人每轮写成 `【姓名】` 后紧接正文，不加冒号；不要写成 `姓名：`。
- 按主题把全文切成带时间戳的小节标题，格式为 `主题（开始—结束）`，时间用中文破折号 `—`。不要把整期对话写成没有小标题的一大段。
- 对照字幕或转写时间轴标注每节起止时间，各节相连并覆盖整期。

### 5. 制作结构化精华版

结构化精华不是“挑选金句和几个重点”，而是对整期节目进行逻辑重组后的全量观点总结。

执行顺序：

1. 从头到尾读取原文润色版。
2. 建立覆盖清单：每当话题、问题、观点、反方意见、案例、方法、条件、数据或结论发生变化，就记录一项。
3. 合并真正重复的内容，但不能删除独立观点。
4. 按节目论述顺序或更清晰的因果顺序分成连续议题；不得按“重要/不重要”筛选。
5. 每个议题写清：提出了什么问题、各方观点、支撑案例、适用条件或限制、得到什么结论。
6. 最后补充可执行清单与代表性原话；它们不能替代完整议题总结。

覆盖检查：逐块回看原文润色版，把每个块映射到结构化精华版中的一个议题。除寒暄、纯重复和无信息口头语外，不允许出现“原文有独立信息，但精华版无对应位置”。

版式必须遵守 [references/output-contract.md](references/output-contract.md) 第 2 节：

- `总结论`、`可执行清单`、`代表性原话` 保持为标题。
- 每个议题写成 `**1. 标题**` 这样的加粗段落，后接列表；不要写成 `### 1. 标题`。
- 议题内部不要再拆更小的标题。这样导入飞书后，文档大纲不会出现一长串议题标题。

### 6. 组装三版本文档

先写结构化精华为独立 Markdown 片段，再运行：

```bash
python3 scripts/assemble_document.py \
  --podcast "<播客名>" \
  --title "<单集标题>" \
  --duration "<HH:MM:SS>" \
  --source "<原始节目 URL>" \
  --engine "FunASR paraformer-zh" \
  --structured "<结构化精华.md>" \
  --polished "<原文润色版.txt>" \
  --raw "<原文无润色版.txt>" \
  --output "<安全文件名>-三版本文档.md"
```

文档顺序固定为：结构化精华版 → 原文润色版 → 原文无润色版。不要只在本地声称保留原文；原文无润色版必须实际嵌入最终文档。

### 7. 可选：同步飞书文档

仅在 `lark-cli auth status --json --verify` 显示有效用户身份后执行。工作交付默认 `--as user`：

```bash
lark-cli docs +create --doc-format markdown \
  --content @<安全文件名>-三版本文档.md --as user
```

如果是更新既有文档，先读取并确认没有需要保留的图片、附件、画板等资源，再用 `overwrite`。Markdown 导入后，如需补齐飞书样式，用 `docs +update` 做 `block_replace`：给润色版小节标题加上 `seq="auto"`；只给 `【姓名】` 着色（第一说话人/主持人蓝 `text-color="blue"`，第二人橙 `text-color="orange"`，第三人绿 `text-color="green"`），不要整段上色。

写入后必须读回验证：三个二级标题、原始链接、原始说话人标记和全文结尾；精华版大纲只有 `总结论` / `可执行清单` / `代表性原话`；润色版大纲是带时间戳的小节标题；说话人是 `【姓名】` 且已分色。

### 8. 最终验收

交付前逐项确认：

- 音频存在且时长合理。
- 原文无润色版非空，且未被后续流程修改。
- 原文润色版包含完整开头、结尾和全部有信息量的内容。
- 结构化精华版按逻辑顺序覆盖全部独立观点，不是精选摘要。
- 最终文档三个版本顺序正确。
- 原文无润色版实际嵌入最终文档。
- 外部播客原始链接存在。
- 如同步飞书，已读回验证而不是只相信写入返回值。
- 精华版议题是加粗正文而不是标题，大纲里没有 `1. …`、`2. …`。
- 润色版有带时间戳的小节标题，说话人使用 `【姓名】`，飞书中不同人名颜色不同。

汇报：输出文件路径或飞书链接、节目时长、结构化议题数、转写引擎，并明确说明原始转写已保留。

## 异常处理

- 同一步失败超过两次：停止，报告失败步骤、错误和已尝试方案。
- 音频格式异常：先转为 16 kHz 单声道 WAV 后重试。
- FunASR 不可用：征得用户同意后再使用云端转写；不要静默上传音频。
- 小宇宙页面取不到音频：改查 RSS；仍失败则请求用户提供可访问链接或本地音频。
- 飞书未配置：交付本地 Markdown，不阻塞转写与文档生成。

## 隐私与分享

- 本地路径默认不上传音频。
- Skill 包不得包含音频、转写内容、模型缓存、账号凭证、Cookie、Token 或用户专属路径。
- 分享给他人时只打包 `SKILL.md`、`scripts/`、`references/` 和可选的 `agents/`。
